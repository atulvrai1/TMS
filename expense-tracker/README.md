# FleetFlow — Docker Setup & Same-Wi-Fi Mobile Access

This guide explains how to run FleetFlow on Ubuntu with Docker and open it from a phone or another computer on the **same local Wi-Fi network**.

## Requirements

- Ubuntu/Linux host
- Docker Engine and Docker Compose v2 (the `docker compose` command)
- This repository checked out locally
- Phone and host computer connected to the same trusted Wi-Fi network

Check Docker:

    docker --version
    docker compose version

If Docker is not installed, Ubuntu packages can be installed with:

    sudo apt update
    sudo apt install -y docker.io docker-compose-v2
    sudo systemctl enable --now docker

If docker-compose-v2 is unavailable for your Ubuntu release, install Docker Engine and the Compose plugin using Docker's official Ubuntu instructions.

## 1. Open the application directory

From the repository root:

    cd ~/TMS/expense-tracker

The Dockerfile and Compose file are in this directory. Run the commands below from here, not from ~/TMS.

## 2. Create your local environment file

    cp .env.docker.example .env.docker
    nano .env.docker

Generate a strong Flask secret key:

    openssl rand -hex 32

Copy the generated value into the FLASK_SECRET_KEY setting in .env.docker. Do not share it or commit the real .env.docker file.

For same-Wi-Fi access, find the Ubuntu host's LAN IP (instructions below), then set FLEETFLOW_PUBLIC_URL in .env.docker to that address, for example:

    FLEETFLOW_PUBLIC_URL=http://192.168.1.8:5001
    PORT=5001

Replace 192.168.1.8 with your host's actual LAN IPv4 address. This public URL setting can be used for links generated by the application; it does not replace the phone's browser URL.

### Make the regular one-command startup work

Compose reads .env by default for variable interpolation. This project keeps its settings in .env.docker, so create a local .env symlink if .env does not already exist.

Check first:

    ls -ld .env 2>/dev/null || true

If no .env file or symlink is shown, run:

    ln -s .env.docker .env

If .env already exists, inspect it first; do not overwrite it blindly.

Alternatively, skip the symlink and explicitly pass the environment file to every Compose command:

    sudo docker compose --env-file .env.docker -f compose.yaml up -d --build

## 3. Build and start FleetFlow

With the symlink configured, run:

    sudo docker compose up -d --build

Check container status:

    sudo docker compose ps

Check the web server from Ubuntu:

    curl -I http://localhost:5001

A successful HTTP response (for example, 200 OK) indicates the application is responding.

View recent logs if there is a problem:

    sudo docker compose logs --tail=100

Follow live logs:

    sudo docker compose logs -f

Press Ctrl+C to stop following logs; the container keeps running.

## 4. Open FleetFlow on a phone over the same Wi-Fi

### A. Find the Ubuntu host's LAN IP

Run:

    hostname -I

Identify the private IPv4 address belonging to the Wi-Fi/LAN, such as 192.168.1.8 or 192.168.0.25. For more detail:

    ip -4 addr

The address may change after a router restart or DHCP renewal. A DHCP reservation in your router can help keep it stable.

### B. Connect both devices to the same network

Connect the phone and Ubuntu computer to the same non-guest Wi-Fi network. If the phone cannot connect, temporarily turn off mobile data to make sure its browser is using Wi-Fi. Guest Wi-Fi or router client isolation may block device-to-device traffic.

### C. Open the app

On the phone, open a browser and visit:

    http://<UBUNTU-LAN-IP>:5001

For example, if the host IP is 192.168.1.8:

    http://192.168.1.8:5001

Do not use localhost on the phone: that refers to the phone itself, not the Ubuntu computer. Use the current LAN IP of the host.

## 5. Firewall troubleshooting

If FleetFlow works at http://localhost:5001 on Ubuntu but not from the phone, check UFW:

    sudo ufw status

If UFW is active, allow port 5001 only from your trusted LAN subnet. Example for a 192.168.1.x network:

    sudo ufw allow from 192.168.1.0/24 to any port 5001 proto tcp

Use your actual subnet; do not copy the example blindly. If you do not know the subnet, check your router/network configuration.

Also verify:

- sudo docker compose ps shows the app running.
- curl -I http://localhost:5001 succeeds on the host.
- The phone and host are on the same Wi-Fi network.
- The phone URL uses the host's current LAN IP and port 5001.
- The router does not have guest-network isolation or AP/client isolation enabled.

## 6. Useful Docker commands

Run these from ~/TMS/expense-tracker.

Start/rebuild:

    sudo docker compose up -d --build

Stop containers (named volumes are retained):

    sudo docker compose down

Restart:

    sudo docker compose restart

View status:

    sudo docker compose ps

View logs:

    sudo docker compose logs --tail=100

Validate Compose configuration:

    sudo docker compose config --quiet

If Compose reports that FLASK_SECRET_KEY is missing, check that .env.docker contains the setting and that .env points to .env.docker, or use the explicit --env-file .env.docker command above.

## 7. Data persistence

Compose creates named volumes for application data and uploads:

- fleetflow_data — database data
- fleetflow_uploads — uploaded files

These volumes persist when the container is rebuilt or stopped. Do not run docker compose down -v unless you intentionally want to delete the named volumes and their data. Back up important application data regularly.

## 8. Security notes

- Same-Wi-Fi access is intended for local development/testing, not public Internet hosting.
- Do not configure router port forwarding for port 5001 just to access the app at home.
- Only allow access from trusted devices and networks.
- Never commit .env, .env.docker, passwords, or real secret keys. Commit only example files containing placeholders.
- For public hosting, configure HTTPS, production secret management, backups, and appropriate application/server security before exposing the service.

## Quick start after first-time setup

Once Docker and the environment file are configured:

    cd ~/TMS/expense-tracker
    sudo docker compose up -d --build
    hostname -I

Then open http://<UBUNTU-LAN-IP>:5001 on a phone connected to the same Wi-Fi.
